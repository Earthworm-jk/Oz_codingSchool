# 5일차 환자 관리 및 진료 기록 API 사용자 요구사항 정의서

## 프로젝트명

흉부 X-Ray AI 진단 서비스

## 1. 문서 목적

이 문서는 의료진/직원 사용자가 환자 정보를 관리하고, 환자별 진료 기록과 X-Ray 이미지를 등록/조회하기 위해 필요한 요구사항을 정리합니다.

이번 프로젝트에서 `users`는 서비스에 로그인하는 의료진/직원 계정이고, `patients`는 의료진/직원이 관리하는 환자 데이터입니다. 따라서 환자는 직접 회원가입하거나 로그인하는 사용자가 아니라, 직원 계정이 등록하고 관리하는 대상 정보로 봅니다.

## 2. 서비스 사용자와 권한

| 사용자 구분 | 설명 | 주요 기능 |
| --- | --- | --- |
| 의료진/직원 사용자 | 로그인 후 환자와 진료 기록을 관리하는 사용자 | 환자 등록, 환자 조회, 진료 기록 등록, X-Ray 이미지 등록 |
| 연구진/개발진 사용자 | 환자 데이터와 분석 결과를 조회할 수 있는 내부 사용자 | 환자 목록 조회, 진료 기록 조회, AI 분석 결과 조회 |
| 관리자 | 시스템 사용자와 권한을 관리하는 사용자 | 전체 데이터 확인, 사용자 권한 관리 |
| 환자 | 진료 대상자 | 직접 로그인하지 않고 직원이 등록/관리 |

## 3. 업무 흐름

```text
직원 로그인
  -> 환자 목록 조회 또는 환자 검색
  -> 환자 등록 또는 환자 상세 조회
  -> 환자별 진료 기록 등록
  -> X-Ray 이미지 업로드
  -> 진료 기록 상세 조회
  -> AI 예측 결과 확인
```

### 기본 사용 시나리오

1. 의료진/직원 사용자가 로그인합니다.
2. 환자 목록에서 기존 환자를 검색하거나 신규 환자를 등록합니다.
3. 환자 상세 화면에서 환자 기본 정보와 진료 기록 목록을 확인합니다.
4. 환자에게 새 진료 기록을 등록하고 X-Ray 이미지를 함께 업로드합니다.
5. 진료 기록 상세 화면에서 증상, 촬영 이미지, AI 예측 결과를 확인합니다.

## 4. 관련 DB 모델

| 테이블 | 역할 |
| --- | --- |
| `patients` | 환자 기본 정보 저장 |
| `medical_records` | 환자별 진료 기록 저장 |
| `xray_images` | 진료 기록에 연결된 X-Ray 이미지 정보 저장 |
| `ai_analysis_results` | AI 폐렴 예측 결과 저장 |
| `users` | 진료 기록 또는 이미지를 등록한 직원/의료진 사용자 |

### 주요 관계

| 관계 | 의미 |
| --- | --- |
| `patients.id` -> `medical_records.patient_id` | 환자 1명은 여러 진료 기록을 가질 수 있음 |
| `medical_records.id` -> `xray_images.record_id` | 진료 기록 1개는 X-Ray 이미지 정보를 가질 수 있음 |
| `users.id` -> `xray_images.uploader_id` | 직원/의료진 사용자가 X-Ray 이미지를 업로드함 |
| `medical_records.id` -> `ai_analysis_results.record_id` | 진료 기록 1개는 여러 AI 분석 결과를 가질 수 있음 |

## 5. 환자 관리 요구사항

| 요구사항 ID | 요구사항 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| REQ-PTNT-001 | 환자 등록 | 의료진/직원 사용자는 환자의 이름, 나이, 성별, 전화번호를 입력하여 신규 환자를 등록할 수 있다. | 필수 |
| REQ-PTNT-002 | 환자 목록 조회 | 로그인한 내부 사용자는 등록된 환자 목록을 조회할 수 있다. | 필수 |
| REQ-PTNT-003 | 환자 상세 조회 | 로그인한 내부 사용자는 환자 ID를 기준으로 특정 환자의 상세 정보를 조회할 수 있다. | 필수 |
| REQ-PTNT-004 | 환자 정보 수정 | 의료진/직원 사용자는 환자의 기본 정보를 수정할 수 있다. | 필수 |
| REQ-PTNT-005 | 환자 삭제 | 의료진/직원 사용자는 잘못 등록된 환자 정보를 삭제할 수 있다. 단, 진료 기록이 있는 환자는 삭제 제한을 검토한다. | 선택 |
| REQ-PTNT-006 | 환자 검색 | 사용자는 이름 또는 전화번호를 기준으로 환자 목록을 검색할 수 있다. | 권장 |

### 5.1 환자 등록 규칙

| 항목 | 타입 | 필수 | 검증 규칙 |
| --- | --- | --- | --- |
| `name` | string | Y | 2자 이상, 30자 이하 |
| `age` | integer | Y | 0 이상, 150 이하 |
| `gender` | string | Y | `male` 또는 `female` |
| `phone` | string | Y | 숫자만 허용, 10자 또는 11자 권장 |

### 5.2 환자 조회 응답 기본 항목

환자 목록과 상세 조회 응답에는 다음 항목을 포함합니다.

```json
{
  "id": 1,
  "name": "홍길동",
  "age": 45,
  "gender": "male",
  "phone": "01012345678",
  "created_at": "2026-06-08T10:00:00",
  "updated_at": "2026-06-08T10:00:00"
}
```

### 5.3 환자 삭제 정책

환자 삭제는 데이터 손실 위험이 있으므로 다음 중 하나의 정책을 선택합니다.

| 정책 | 설명 | 추천 여부 |
| --- | --- | --- |
| 진료 기록 없는 환자만 삭제 | 연결된 진료 기록이 없을 때만 삭제 허용 | 1차 구현 추천 |
| 진료 기록까지 함께 삭제 | 환자 삭제 시 진료 기록, X-Ray 이미지, AI 결과도 함께 삭제 | 신중 필요 |
| 삭제 API 제외 | 환자 삭제를 구현하지 않고 수정/조회만 제공 | 가능 |

1차 구현에서는 의료 데이터 보존을 위해 **진료 기록이 있는 환자는 삭제하지 못하게 막는 정책**을 추천합니다.

## 6. 진료 기록 요구사항

| 요구사항 ID | 요구사항 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| REQ-MDR-001 | 진료 기록 등록 | 의료진/직원 사용자는 특정 환자에게 증상, 차트번호, X-Ray 이미지를 포함한 진료 기록을 등록할 수 있다. | 필수 |
| REQ-MDR-002 | 환자별 진료 기록 목록 조회 | 사용자는 특정 환자에게 등록된 진료 기록 목록을 조회할 수 있다. | 필수 |
| REQ-MDR-003 | 진료 기록 상세 조회 | 사용자는 진료 기록 ID를 기준으로 상세 내용을 조회할 수 있다. | 필수 |
| REQ-MDR-004 | 진료 기록 수정 | 의료진/직원 사용자는 증상 또는 X-Ray 이미지 정보를 수정할 수 있다. | 선택 |
| REQ-MDR-005 | 차트번호 중복 방지 | 동일한 차트번호가 중복 등록되지 않도록 한다. | 필수 |

### 6.1 진료 기록 등록 규칙

진료 기록 등록은 텍스트 데이터와 이미지 파일을 함께 받을 가능성이 있으므로 `multipart/form-data` 형식을 사용합니다.

| 항목 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `patient_id` | integer | Y | 진료 기록을 연결할 환자 ID |
| `chart_number` | string | Y | 진료 차트 번호, 중복 불가 |
| `symptoms` | string | Y | 환자의 증상 또는 진료 메모 |
| `xray_image` | file | N | X-Ray 이미지 파일. 진료 기록만 먼저 등록할 수 있으며, 이미지가 있는 경우 함께 저장 |
| `shooting_datetime` | datetime | N | X-Ray 촬영 일시. 미입력 시 서버 현재 시각으로 저장 |

### 6.2 진료 기록 상세 응답 기본 항목

프론트엔드의 진료 기록 상세 화면은 X-Ray 이미지를 바로 보여줘야 하므로, 응답에는 `xray_image_url`을 포함하는 것을 권장합니다.

```json
{
  "id": 1,
  "patient_id": 1,
  "chart_number": "CHART-20260608-001",
  "symptoms": "기침, 발열, 흉부 통증",
  "xray_image_url": "/media/xray/record_1.png",
  "shooting_datetime": "2026-06-08T09:30:00",
  "created_at": "2026-06-08T10:00:00"
}
```

### 6.3 진료 기록 목록 응답 기본 항목

환자 상세 화면의 진료 기록 목록에서는 너무 많은 정보를 보여줄 필요가 없으므로 핵심 항목만 반환합니다.

```json
[
  {
    "id": 1,
    "patient_id": 1,
    "chart_number": "CHART-20260608-001",
    "symptoms": "기침, 발열",
    "created_at": "2026-06-08T10:00:00"
  }
]
```

| REQ-MDR-003 | 진료 기록 상세 조회 | `GET` | `/api/v1/medical-records/{record_id}` | Y | 진료 기록 상세 조회 |

## 8. 인증 및 권한 요구사항

환자와 진료 기록 정보는 민감한 의료 정보이므로 기본적으로 로그인한 사용자만 접근할 수 있어야 합니다.

| API 구분 | 접근 가능 사용자 |
| --- | --- |
| 환자 등록/수정/삭제 | 의료진 또는 관리자 |
| 환자 목록/상세 조회 | 로그인한 내부 사용자 |
| 진료 기록 등록 | 의료진 또는 관리자 |
| 진료 기록 조회 | 로그인한 내부 사용자 |
| AI 분석 결과 조회 | 로그인한 내부 사용자 |

구현 초반에는 인증 로직이 완성되지 않았을 수 있으므로, 1차 개발에서는 CRUD를 먼저 구현하고 User API의 인증 기능이 완성된 뒤 `Depends(get_current_user)` 형태로 인증 의존성을 연결합니다.

## 9. 실패 응답 정책

| 상황 | HTTP Status | 응답 예시 |
| --- | --- | --- |
| 환자 ID가 존재하지 않음 | 404 Not Found | `{"detail": "존재하지 않는 환자입니다."}` |
| 진료 기록 ID가 존재하지 않음 | 404 Not Found | `{"detail": "존재하지 않는 진료 기록입니다."}` |
| 필수 입력 누락 | 422 Unprocessable Entity | FastAPI/Pydantic 기본 검증 응답 |
| 차트번호 중복 | 400 Bad Request | `{"detail": "이미 등록된 차트번호입니다."}` |
| 진료 기록이 있는 환자 삭제 시도 | 400 Bad Request | `{"detail": "진료 기록이 있는 환자는 삭제할 수 없습니다."}` |
| 로그인하지 않은 사용자 접근 | 401 Unauthorized | `{"detail": "인증이 필요합니다."}` |
| 권한 없는 사용자 접근 | 403 Forbidden | `{"detail": "접근 권한이 없습니다."}` |

## 10. 구현 우선순위 제안

3명이 나누어 개발할 경우, 다음 순서로 진행하면 충돌을 줄일 수 있습니다.

| 순서 | 작업 | 이유 |
| --- | --- | --- |
| 1 | 환자 등록/목록/상세 API | 진료 기록은 환자 ID가 있어야 등록 가능 |
| 2 | 진료 기록 등록/목록/상세 API | 환자 상세 화면과 X-Ray 이미지 등록 흐름 연결 |
| 3 | 환자 수정/삭제 API | 기본 조회/등록 흐름이 안정된 뒤 확장 |
| 4 | 인증 의존성 연결 | User API의 로그인/JWT 구조가 확정된 뒤 연결 |
| 5 | AI 예측 API 연결 | 진료 기록과 X-Ray 이미지 저장 흐름이 완성된 뒤 연결 |

## 11. 단계 완료 기준

다음 항목이 확인되면 환자 관리 및 진료 기록 API 설계 단계가 완료된 것으로 봅니다.

- 환자와 진료 기록의 사용자 요구사항이 문서화되어 있음
- API 후보의 Method, Endpoint, 인증 필요 여부가 정리되어 있음
- 환자와 진료 기록이 어떤 DB 테이블과 연결되는지 설명되어 있음
- 프론트엔드가 기대하는 주요 응답 필드가 정리되어 있음
- 향후 구현 시 우선순위와 역할 분담 기준으로 사용할 수 있음

## 12. 참고 사항

- 현재 프론트엔드는 `/api/v1/patients`, `/api/v1/medical-records` 계열 API를 기대합니다.
- 환자 데이터는 `patients` 테이블, 진료 기록은 `medical_records` 테이블, X-Ray 이미지는 `xray_images` 테이블에 나누어 저장하는 구조가 자연스럽습니다.
- X-Ray 이미지 파일 자체는 DB에 직접 저장하지 않고, 파일 경로 또는 접근 URL을 DB에 저장하는 방식을 권장합니다.
- 현재 구현에서는 진료 기록 등록 시 X-Ray 이미지와 촬영 일시는 선택 입력으로 처리하며, 촬영 일시가 비어 있으면 서버 현재 시각을 기본값으로 저장합니다.
- AI 예측 결과는 진료 기록 상세 화면에서 조회되지만, 실제 예측 기능은 별도 AI API 구현 단계에서 다룹니다.
