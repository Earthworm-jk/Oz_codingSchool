DB Migration Mission Guide

Alembic이 뭐고, 이번 과제에서 어떻게 쓰는가

이 문서는 팀원이 같은 그림을 보고 움직일 수 있도록 Alembic의 역할, SQLAlchemy 모델과의 관계, 이번 ERD 미션 진행 순서를 초보자 기준으로 정리한 가이드입니다.

SQLAlchemy Model Python 코드로 작성한 DB 테이블 설계도입니다.
Alembic 모델 변경 내용을 DB에 반영하는 migration 도구입니다.
Migration File DB에 실행할 변경 작업을 기록한 버전 파일입니다.
DB Viewer 실제 DB에 테이블이 생겼는지 확인하는 도구입니다.

1. Alembic을 한 문장으로 이해하기

Alembic은 SQLAlchemy 모델의 변경 사항을 실제 데이터베이스 스키마에 반영하기 위한 버전 관리 도구입니다.

설계 ERD 어떤 테이블과 컬럼이 필요한지 그림으로 정리합니다.
코드 SQLAlchemy Model ERD를 Python 클래스로 옮깁니다.
기록 Migration 생성 Alembic이 모델과 DB 차이를 migration 파일로 만듭니다.
반영 Upgrade migration 파일의 내용을 실제 DB에 적용합니다.
검증 DB Viewer 테이블, 컬럼, 관계가 생겼는지 눈으로 확인합니다.
비유로 보면: SQLAlchemy 모델은 건물 설계도, Alembic migration 파일은 공사 지시서, DB는 실제 건물입니다. 설계도만 고쳐서는 실제 건물이 바뀌지 않기 때문에 Alembic으로 DB에 반영해야 합니다.

3. 이번 프로젝트에서 이미 준비된 것

우리 프로젝트에는 Alembic을 새로 초기화하지 않아도 되는 기본 구성이 이미 있습니다.

파일 역할 이번 미션에서 보는 포인트
pyproject.toml Alembic, SQLAlchemy, asyncmy 의존성 관리 alembic이 이미 설치 대상으로 포함되어 있습니다.
app/core/db/databases.py DB 접속 주소, 엔진, 세션, Base 정의 모든 모델은 여기의 Base를 상속받아야 합니다.
alembic/env.py Alembic이 모델 정보를 읽고 DB에 접속하는 설정 target_metadata = Base.metadata로 연결되어 있습니다.
app/models/__init__.py 모델들을 한 번에 import하는 입구 여기에 모델 import가 빠지면 autogenerate가 테이블을 못 볼 수 있습니다.
alembic/versions/ migration 파일들이 저장되는 폴더 이번 미션에서 새 migration 파일이 생겨야 합니다.

4. 이번 ERD를 모델로 옮기기

첨부된 ERD 기준으로 작성할 테이블은 다음 5개입니다.

users

  • 회원/의료진 계정 정보
  • email, hashed_password, name
  • gender, department, role
  • 팀 확장 필드: nationality, first_name, last_name, middle_name, employee_number
  • xray_images의 uploader가 됩니다.

patients

  • 환자 기본 정보
  • name, age, gender, phone
  • medical_records와 연결됩니다.

medical_records

  • 환자 진료 기록
  • patient_id, chart_number, symptoms
  • xray_images, ai_analysis_results와 연결됩니다.

xray_images

  • X-ray 이미지 정보
  • record_id, uploader_id, image_url
  • 진료 기록과 업로더 계정을 참조합니다.

ai_analysis_results

  • AI 분석 결과
  • record_id, is_pneumonia, confidence
  • 분석 모델명과 heatmap URL을 저장합니다.
우리 팀 반영 방향: 팀에서 회원가입/API 확장 방향을 유지하기로 했으므로, ERD의 users 기본 구조에 국적, 이름 분리, 사번 필드를 추가해서 모델을 작성합니다. 즉, 과제 ERD를 기본 뼈대로 삼되 실제 회원가입 화면과 API가 보내는 데이터 구조까지 DB 모델에 맞춰주는 방식입니다.
필드 추천 컬럼 이유
국적 구분 nationality = Column(Enum(...), nullable=False) 내국인/외국인에 따라 이름 입력 방식과 검증 메시지가 달라집니다.
이름 분리 last_name, first_name, middle_name 성/이름/미들네임을 분리해서 내국인과 외국인 이름 구조를 모두 표현합니다.
화면 표시용 이름 name ERD의 기존 컬럼을 유지하되, 필요하면 서버에서 조합한 전체 이름을 저장하거나 표시용으로 사용할 수 있습니다.
중복 가입 방지 employee_number = Column(String(...), unique=True, nullable=False) email 외에도 사번을 기준으로 중복 회원가입을 막을 수 있습니다.
비밀번호 확인 DB 컬럼으로 저장하지 않음 비밀번호 확인값은 가입 요청 검증용입니다. DB에는 hashed_password만 저장하는 것이 맞습니다.

5. 실제 작업 순서

dev에서 feature 브랜치 생성

DB 모델 작업은 별도 브랜치에서 진행합니다.

git switch dev
git pull origin dev
git switch -c feature/db-models-migration

모델 파일 생성

app/models/ 아래에 테이블별 파일을 만듭니다.

app/models/users.py
app/models/patients.py
app/models/medical_records.py
app/models/xray_images.py
app/models/ai_analysis_results.py

각 모델 클래스 작성

각 클래스는 Base를 상속하고, __tablename__과 컬럼을 정의합니다.

class Patient(Base):
    __tablename__ = "patients"

    id = Column(BigInteger, primary_key=True, autoincrement=True)
    name = Column(String(30), nullable=False)
    age = Column(SmallInteger, nullable=False)

모델 import 연결

app/models/__init__.py에서 만든 모델들을 import합니다. Alembic이 이 import를 통해 모델을 발견합니다.

from app.models.users import User
from app.models.patients import Patient
from app.models.medical_records import MedicalRecord
from app.models.xray_images import XrayImage
from app.models.ai_analysis_results import AiAnalysisResult

migration 파일 자동 생성

모델과 현재 DB 상태를 비교해서 migration 파일을 만듭니다.

uv run alembic revision --autogenerate -m "create medical schema"

migration 파일 검토

생성된 파일에서 의도한 테이블만 생성되는지 확인합니다.

  • create_table("users", ...)가 있는가
  • create_table("patients", ...)가 있는가
  • 외래키 ForeignKey가 맞게 생성되었는가
  • 예상하지 못한 drop_table, drop_column이 없는가

DB에 migration 적용

검토가 끝나면 실제 DB에 스키마를 반영합니다.

uv run alembic upgrade head

DB Viewer로 확인

MySQL DB에 접속해서 테이블, 컬럼, FK가 보이는지 확인하고 캡처합니다.

  • users, patients, medical_records 테이블 확인
  • xray_images, ai_analysis_results 테이블 확인
  • 외래키 관계가 보이는지 확인

문서 작성 후 PR

docs/3일차_db_migration.md에 DB Viewer 캡처와 진행 내용을 정리한 뒤 PR을 올립니다.

git add app/models alembic/versions docs/3일차_db_migration.md
git commit -m "feat: add db models and migration"
git push origin feature/db-models-migration

6. 자주 쓰는 Alembic 명령어

명령어 뜻 이번 과제에서 사용 여부
alembic init alembic Alembic 기본 폴더와 설정 파일을 처음 생성합니다. 이미 설정되어 있으므로 보통 사용하지 않습니다.
alembic revision -m "message" 빈 migration 파일을 직접 만듭니다. 이번에는 자동 생성이 더 편합니다.
alembic revision --autogenerate -m "message" 모델과 DB 차이를 비교해 migration 파일을 만듭니다. 사용합니다.
alembic upgrade head 가장 최신 migration까지 DB에 적용합니다. 사용합니다.
alembic downgrade -1 migration을 한 단계 되돌립니다. 실수 복구용입니다. 팀장/담당자와 상의 후 사용합니다.
alembic current 현재 DB가 어떤 migration 버전인지 확인합니다. 문제 확인 시 유용합니다.
alembic history migration 이력을 확인합니다. PR 리뷰 때 참고할 수 있습니다.
우리 프로젝트에서는 명령 앞에 uv run을 붙이는 방식이 안전합니다. 예: uv run alembic upgrade head

7. 모델 작성 시 타입 매핑

ERD 타입 SQLAlchemy 타입 예시 설명
integer Integer 일반 정수 id 등에 사용합니다.
bigint BigInteger 큰 정수 id에 사용합니다.
smallint SmallInteger 나이처럼 작은 숫자에 사용합니다.
varchar(30) String(30) 길이 제한이 있는 문자열입니다.
text Text 증상 설명처럼 긴 문자열에 사용합니다.
datetime DateTime 생성일, 수정일, 촬영일시에 사용합니다.
bool, boolean Boolean 폐렴 여부, 활성 여부 같은 참/거짓 값입니다.
decimal(5,2) DECIMAL(5, 2) AI confidence처럼 소수점 자릿수가 중요한 값입니다.
enum Enum(...) gender, department, role처럼 정해진 값 중 하나만 허용합니다.

8. PR 리뷰에서 확인할 것

모델 파일 확인
  • ERD의 5개 테이블이 모두 있는가
  • 컬럼명과 타입이 ERD와 맞는가
  • nullable=False가 필요한 곳에 있는가
  • unique 컬럼이 반영되었는가
관계 확인
  • patient_id가 patients.id를 참조하는가
  • record_id가 medical_records.id를 참조하는가
  • uploader_id가 users.id를 참조하는가
migration 확인
  • 새 migration 파일이 생성되었는가
  • 의도한 테이블 생성만 들어있는가
  • 불필요한 삭제 작업이 없는가
실행 결과 확인
  • alembic upgrade head가 성공했는가
  • DB Viewer에서 테이블이 보이는가
  • docs/3일차_db_migration.md에 캡처가 있는가

9. 흔한 실수와 해결법

상황 원인 해결
autogenerate 했는데 migration 파일이 비어 있음 모델이 import되지 않아 Alembic이 못 봄 app/models/__init__.py에서 모든 모델을 import합니다.
DB 접속 오류 MySQL 컨테이너가 꺼져 있거나 .env 설정이 맞지 않음 docker compose up 상태와 DB 환경변수를 확인합니다.
외래키 생성 오류 참조 테이블명 또는 컬럼 타입이 맞지 않음 부모 테이블 이름과 id 타입을 다시 맞춥니다.
예상치 못한 drop 코드가 생성됨 현재 DB와 모델 차이를 Alembic이 삭제로 판단함 migration 파일을 바로 적용하지 말고 팀원과 먼저 확인합니다.
팀원 DB에는 테이블이 없음 migration 파일만 pull 받고 upgrade를 실행하지 않음 uv run alembic upgrade head를 각자 실행합니다.

10. 이번 미션 완료 조건 체크리스트

  • app/models/__init__.py에서 모델들이 import되어 있다.
  • alembic/versions/ 아래에 새 migration 파일이 있다.
  • uv run alembic upgrade head가 성공했다.
  • DB Viewer에서 5개 테이블과 주요 관계를 확인했다.
  • docs/3일차_db_migration.md에 DB 확인 이미지와 설명을 작성했다.
