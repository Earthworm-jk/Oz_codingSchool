# 프로젝트 템플릿 분석 가이드

AI Health Web Assignment

이 문서는 우리 팀이 받은 FastAPI 기반 AI 의료 웹서비스 템플릿을 초보자 관점에서 쉽게 이해하기 위해 정리한 안내서입니다. 현재 무엇이 준비되어 있고, 무엇을 앞으로 구현해야 하는지 한눈에 볼 수 있게 구성했습니다. 이 프로젝트의 주요 사용자는 환자가 아니라 환자 정보를 관리하는 의료진/직원 계정으로 해석합니다.

## 요약

| 구분 | 내용 |
| --- | --- |
| 서비스 주제 | 흉부 X-Ray 이미지로 폐렴 여부를 예측하는 진단 지원 웹서비스 |
| 백엔드 | FastAPI, SQLAlchemy 비동기 DB, Alembic 마이그레이션 |
| 프론트엔드 | 정적 HTML, CSS, JavaScript로 만든 SPA 형태의 화면 |
| 배포/인프라 | Docker Compose로 FastAPI와 MySQL을 함께 실행하는 구조 |

## 1. 이 프로젝트는 어떤 프로젝트인가?

한 줄로 말하면 **AI 폐렴 진단 지원 시스템**입니다. 의료진/직원 사용자가 회원가입과 로그인을 하고, 환자 정보를 관리하며, 환자의 진료 기록과 X-Ray 이미지를 등록한 뒤, AI 모델로 폐렴 여부를 예측하는 웹서비스를 만드는 것이 목표입니다.

**중요한 해석**

현재 템플릿은 완성된 앱이 아닙니다. 프론트 화면과 API 호출 목록은 꽤 구체적으로 준비되어 있지만, 실제 FastAPI 백엔드 기능은 대부분 비어 있습니다. 즉 앞으로 우리 팀이 백엔드, DB 모델, 인증, AI 추론, Docker 배포를 단계별로 채워 넣어야 합니다.

**서비스 주체 해석**

ERD와 현재 회원가입 UI를 함께 보면 `users`는 환자 계정이 아니라 서비스에 로그인하는 의료진/직원 계정으로 보는 것이 자연스럽습니다. `patients`는 의료진/직원이 등록하고 조회하는 환자 정보입니다. 따라서 회원가입에는 사번, 부서, 역할, 국적, 이름 분리 같은 직원 계정용 정보가 포함될 수 있고, 환자는 별도의 `patients` 테이블에서 관리합니다.

## 2. 전체 구조 한눈에 보기

웹서비스는 보통 **사용자 행동 → 서버 요청 → 데이터 처리 → 화면 갱신**의 흐름으로 움직입니다. 이 프로젝트에서 데이터가 오가는 길은 아래와 같습니다.

### 1단계: 사용자 행동

| 순서 | 담당 | 동작 | 설명 |
| --- | --- | --- | --- |
| 1 | 브라우저 | 화면에서 버튼 클릭 | 예: 직원 로그인, 환자 목록 보기, X-Ray 업로드, AI 예측 결과보기 |
| 2 | JavaScript | 필요한 API 결정 | `static/app.js`와 `static/pages.js`가 어떤 화면인지 판단합니다. |
| 3 | JavaScript | 요청 만들기 | `static/apis.js`가 주소, method, token, body를 준비합니다. |
| 4 | FastAPI | 서버로 전송 | 요청 주소는 대부분 `/api/v1/...` 형태입니다. |

### 2단계: 서버 처리

| 순서 | 담당 | 동작 | 설명 |
| --- | --- | --- | --- |
| 5 | FastAPI | 요청 받기 | 라우터가 요청을 받고, 어떤 기능인지 구분합니다. |
| 6 | 인증/권한 | 직원/의료진 사용자 확인 | 로그인 토큰, 승인 상태, 관리자 권한을 확인합니다. |
| 7 | MySQL | DB 작업 | 직원 계정, 환자, 진료 기록, 예측 결과를 조회하거나 저장합니다. |
| 8 | AI 모델 | 예측 실행 | AI 예측 요청일 때만 X-Ray 이미지를 모델에 넣어 결과를 계산합니다. |

### 3단계: 화면 갱신

| 순서 | 담당 | 동작 | 설명 |
| --- | --- | --- | --- |
| 9 | FastAPI | JSON 응답 | DB나 AI 모델 결과를 프론트가 읽을 수 있는 JSON으로 돌려줍니다. |
| 10 | JavaScript | 응답 해석 | 받은 데이터를 표, 상세 정보, 알림 메시지 형태로 바꿉니다. |
| 11 | 브라우저 | 화면 표시 | 직원/의료진 사용자는 환자 목록, 진료 기록, AI 예측 결과를 화면에서 봅니다. |
| 12 | 다음 행동 | 다시 반복 | 직원/의료진 사용자가 다른 버튼을 누르면 같은 흐름이 다시 시작됩니다. |

### 기능 흐름 예시

**환자 목록 보기**

`환자 목록 보기`를 누르면 JavaScript가 `GET /api/v1/patients`를 호출하고, FastAPI가 MySQL에서 환자 목록을 가져와 화면에 표로 보여줍니다. 이때 AI 모델은 사용하지 않습니다.

**AI 예측 결과보기**

`AI 예측 결과보기`를 누르면 FastAPI가 진료 기록의 X-Ray 이미지를 찾고, AI 모델로 폐렴 여부를 예측한 뒤 결과를 MySQL에 저장하고 화면에 보여줍니다.

**쉽게 기억하기**

프론트엔드는 **보여주고 요청하는 역할**, FastAPI는 **판단하고 처리하는 역할**, MySQL은 **기억하는 역할**, AI 모델은 **X-Ray를 분석하는 역할**입니다.

## 3. 폴더별 역할

| 폴더/파일 | 역할 |
| --- | --- |
| `app/` | FastAPI 백엔드 코드가 들어가는 폴더입니다. 현재는 앱 실행 파일과 DB 설정 정도만 있고, 실제 API 라우터, 모델, 스키마, 서비스, 저장소 코드는 대부분 비어 있습니다. |
| `static/` | 브라우저에서 보이는 화면입니다. HTML 템플릿, CSS, JavaScript가 들어 있습니다. 프론트가 어떤 API를 기대하는지 확인하는 데 가장 중요한 힌트가 됩니다. |
| `alembic/` | DB 테이블 변경 이력을 관리하는 마이그레이션 도구입니다. SQLAlchemy 모델을 만든 뒤 Alembic으로 실제 MySQL 테이블을 생성하거나 변경합니다. |
| `docs/` | 팀 규칙이나 프로젝트 설명 문서를 모아두는 폴더입니다. 이 가이드 문서도 여기에 추가했습니다. |
| `docker-compose.yml` | FastAPI 서버와 MySQL 서버를 Docker로 함께 실행하기 위한 설정입니다. 다만 `app/Dockerfile`이 아직 비어 있어서 배포 단계에서 작성해야 합니다. |

## 4. 현재 구현되어 있는 것

### 백엔드 쪽

- `app/main.py`에서 FastAPI 앱을 생성합니다.
- `/healthcheck`로 서버 상태를 확인할 수 있습니다.
- `/static` 경로로 CSS/JS/HTML 파일을 제공합니다.
- `/media` 경로로 업로드 파일을 제공할 준비가 되어 있습니다.
- MySQL에 비동기로 연결하는 SQLAlchemy 설정이 있습니다.
- Alembic 마이그레이션을 사용할 수 있는 설정이 있습니다.

### 프론트엔드 쪽

- 로그인, 회원가입 화면이 있습니다.
- 환자 목록, 환자 등록, 환자 상세 화면이 있습니다.
- 진료 기록 등록과 X-Ray 이미지 미리보기 화면이 있습니다.
- AI 예측 결과를 보여주는 화면이 있습니다.
- 관리자용 회원 관리 화면이 있습니다.
- 토큰 만료 시 refresh 요청을 보내는 흐름이 들어 있습니다.

## 5. 아직 비어 있거나 구현해야 하는 것

1. **DB 모델 작성**  
   User, Patient, MedicalRecord, Analysis 같은 테이블 구조를 SQLAlchemy 모델로 만들어야 합니다.
2. **Pydantic 스키마 작성**  
   API 요청과 응답의 모양을 정의합니다. 예: 회원가입 요청, 환자 응답, 예측 결과 응답.
3. **API 라우터 작성**  
   프론트가 호출하는 `/api/v1/users`, `/api/v1/patients`, `/api/v1/medical-records`, `/api/v1/admin` 엔드포인트를 구현해야 합니다.
4. **인증과 권한 처리**  
   JWT access token, refresh token cookie, 관리자 권한, 승인 대기 사용자 제한을 구현해야 합니다.
5. **파일 업로드 처리**  
   X-Ray 이미지를 받아 `media/` 폴더에 저장하고, DB에는 이미지 URL이나 경로를 저장해야 합니다.
6. **AI 모델 서빙**  
   진료 기록에 저장된 X-Ray 이미지를 모델에 넣고, 폐렴 여부와 confidence를 계산해 DB에 저장해야 합니다.
7. **Dockerfile 작성**  
   현재 `app/Dockerfile`은 비어 있습니다. FastAPI 서버를 컨테이너에서 실행할 수 있게 작성해야 합니다.

## 6. 프론트가 기대하는 API 목록

초보자에게 가장 좋은 힌트는 `static/apis.js`입니다. 이 파일을 보면 프론트가 어떤 주소로 어떤 요청을 보내는지 알 수 있습니다.

| 기능 | HTTP | 주소 | 설명 |
| --- | --- | --- | --- |
| 회원가입 | `POST` | `/api/v1/users/signup` | 의료진/직원 계정을 생성합니다. 이메일, 비밀번호, 사번, 부서, 역할, 성별, 전화번호, 국적과 이름 정보를 입력합니다. |
| 로그인 | `POST` | `/api/v1/users/login` | access token을 JSON으로 받고 refresh token은 HTTP-only cookie로 받는 구조를 기대합니다. |
| 내 정보 | `GET/PATCH/DELETE` | `/api/v1/users/me` | 현재 로그인한 직원/의료진 사용자 조회, 수정, 탈퇴를 처리합니다. |
| 관리자 회원 관리 | `GET/PATCH` | `/api/v1/admin/users`, `/api/v1/admin/users/role` | 관리자가 직원/의료진 회원 목록을 보고 다른 사용자의 권한을 수정합니다. |
| 환자 관리 | `POST/GET/PATCH/DELETE` | `/api/v1/patients`, `/api/v1/patients/{id}` | 환자 등록, 목록 조회, 상세 조회, 수정, 삭제를 처리합니다. |
| 진료 기록 | `POST/GET` | `/api/v1/medical-records`, `/api/v1/patients/{id}/medical-records` | 환자별 진료 기록과 X-Ray 이미지를 등록하고 조회합니다. |
| AI 예측 | `POST/GET` | `/api/v1/medical-records/{id}/predict`, `/api/v1/medical-records/{id}/analyses` | 저장된 X-Ray 이미지로 폐렴 예측을 수행하고 결과 목록을 조회합니다. |

## 7. 추천 개발 순서

1. **먼저 프론트 화면을 눌러본다.** 어떤 화면에서 어떤 데이터가 필요한지 감을 잡습니다.
2. **DB 모델을 설계한다.** User는 직원/의료진 계정, Patient는 환자 정보로 보고 MedicalRecord, Analysis의 관계를 정합니다.
3. **직원/의료진 회원가입과 로그인부터 구현한다.** 인증이 되어야 다른 화면을 제대로 테스트할 수 있습니다.
4. **환자 CRUD를 구현한다.** 목록, 검색, 등록, 상세, 수정, 삭제를 차례대로 붙입니다.
5. **진료 기록과 이미지 업로드를 구현한다.** 파일 저장 경로와 DB 저장 값을 명확히 정합니다.
6. **AI 예측 API를 구현한다.** 처음에는 더미 결과로 연결하고, 나중에 실제 모델로 교체해도 됩니다.
7. **Alembic migration을 만든다.** 모델 변경 후 DB 테이블을 자동 생성합니다.
8. **Dockerfile과 docker-compose를 정리한다.** 팀원 모두 같은 방식으로 실행할 수 있게 만듭니다.

**초보 팀에게 추천**

처음부터 AI 모델까지 한 번에 붙이려고 하면 복잡합니다. 먼저 직원/의료진 로그인, 환자 관리, 진료 기록 저장이 되는 작은 웹서비스를 완성하고, 그다음 예측 API를 더미 결과에서 실제 모델로 바꾸는 방식이 안전합니다.

## 8. 주의해야 할 부분

- **Docker 안의 DB 주소:** 로컬에서 실행할 때는 `DB_HOST=localhost`가 맞을 수 있지만, Docker Compose 내부에서는 보통 `DB_HOST=mysql`이어야 합니다.
- **Dockerfile:** `app/Dockerfile`이 비어 있으므로 Docker 배포 미션에서 반드시 작성해야 합니다.
- **Python 버전:** `pyproject.toml`은 Python `>=3.13`을 요구합니다. 팀원 PC의 Python 버전이 낮으면 실행이 안 될 수 있습니다.
- **프론트와 백엔드 응답 모양:** 프론트는 `access_token`, `role`, `phone_number`, `employee_number`, `nationality`, `xray_image_url`, `confidence` 같은 필드명을 기대합니다. 백엔드 응답 필드명을 맞춰야 화면이 깨지지 않습니다.
- **권한:** 승인 대기 사용자는 대부분의 화면에 접근할 수 없고, 관리자만 회원 관리 화면에 접근할 수 있게 되어 있습니다.

## 9. 초보자용 핵심 용어

| 용어 | 쉽게 말하면 |
| --- | --- |
| FastAPI | 브라우저나 프론트엔드가 보낸 요청을 받아 처리하는 Python 웹 서버 프레임워크입니다. |
| API | 프론트엔드와 백엔드가 약속한 대화 창구입니다. 예: `GET /api/v1/patients` |
| SQLAlchemy | Python 코드로 DB 테이블과 데이터를 다루게 해주는 도구입니다. |
| Alembic | DB 테이블 구조 변경 이력을 관리하는 도구입니다. |
| JWT | 로그인한 사용자인지 확인하기 위해 주고받는 토큰입니다. |
| Docker | 팀원마다 다른 컴퓨터 환경에서도 같은 방식으로 서버를 실행하게 해주는 컨테이너 도구입니다. |
| Model Serving | 학습된 AI 모델을 웹서비스에서 호출할 수 있도록 서버 기능으로 연결하는 작업입니다. |

## 10. 결론

이 템플릿은 **프론트 화면과 API 요구사항이 먼저 준비된 백엔드 구현 과제**입니다. 우리 팀은 의료진/직원 사용자가 환자 정보와 X-Ray 분석 결과를 관리하는 흐름을 기준으로 API를 FastAPI로 하나씩 구현하고, DB와 AI 모델, Docker 배포까지 연결하면서 완성도를 높이면 됩니다.

처음 공부할 때는 `static/apis.js`를 API 명세서처럼 보고, `static/pages.js`를 화면 동작 설명서처럼 보면 이해가 훨씬 쉬워집니다.
